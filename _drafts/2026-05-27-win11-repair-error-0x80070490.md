
Error 0x80070490

To fix Error 0x80070490, you should use tools that repair corrupted files and component data:

1. Run the Component Repair Tools

Since the error represents missing files, use the Deployment Image Servicing and Management (DISM) tool followed by the System File Checker (SFC) to rebuild the Component Store.

Open Command Prompt as an Administrator.

Paste the following command to check and repair the component repository:

cmd

DISM /Online /Cleanup-Image /RestoreHealth

Once finished, run the file repair scanner:

cmd

sfc /scannow

Restart your computer and try the update again.

If that fails then try resetting Windows update Components

Reset Windows Update Components

If the error persists, the update cache itself may be broken. You can flush out the old files using these commands in an administrative Command Prompt:

```
net stop wuauserv
net stop cryptSvc
net stop bits
net stop msiserver
ren C:\Windows\SoftwareDistribution SoftwareDistribution.old
ren C:\Windows\System32\catroot2 catroot2.old
net start wuauserv
net start cryptSvc
net start bits
net start msiserver
```

Clear Stale Driver Registry Entries

According to Microsoft Documentation for Error 0x80070490, this error often occurs when a broken driver operation is locked in the registry.

Press Win + R, type regedit, and press Enter.

Navigate to: HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\DriverOperations

Look for a subkey named simply 1. If it exists under DriverOperations, right-click and Delete it.

Extract the Relevant Error Lines

Because the CBS log can be massive, the fastest way to find what is missing is to filter it using PowerShell:

```powershell
Get-Content "C:\Windows\Logs\CBS\CBS.log" | Select-String "0x80070490" | Select-Object -Last 20
```

The log shows that your Windows Update system is choking on three specific, corrupted system packages: Windows Defender Application Guard, Windows Search Engine, and FodMetadataServicing.

Because these packages are missing critical data in the registry, the update aborts completely. You can force Windows to rebuild or ignore these broken paths using the following targeted fixes.

## Fix 1: Manually Remove the Corrupted FodMetadata Package
The very last line shows Windows completely unable to open a specific Feature-on-Demand (Fod) Metadata package (...26100.8457). We can force-remove it via the Deployment Image Servicing and Management (DISM) tool.

   1. Right-click the Start menu and open Terminal (Admin) or PowerShell (Admin).
   2. Copy and paste this exact command, then press Enter:
   dism /online /remove-package /packagename:Microsoft-Windows-FodMetadataServicing-Desktop-Metadata-Package~31bf3856ad364e35~amd64~~10.0.26100.8457
   3. If it completes successfully, restart your PC and try running Windows Update again.

## Fix 2: Repair the System Hive via Registry
The log also notes: Failed to read PreviousCurrentBuildNumber from the registry. This usually indicates that the servicing keys are misconfigured.

   1. Press Win + R, type regedit, and press Enter to open the Registry Editor.
   2. Navigate to this exact path in the left sidebar:
   HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing
   3. Look for a subkey folder inside it called ApplicabilityEvaluationCache.
   4. Right-click ApplicabilityEvaluationCache and select Delete. (Windows will automatically rebuild a clean version of this cache on the next reboot).
   5. Restart your computer.

## Fix 3: The Definitive Solution (In-Place Upgrade)
If the DISM package removal in Fix 1 fails with an error, it means the underlying registry corruption is too severe for command-line fixes. The absolute best and most efficient way to repair this without losing any files or apps is an In-Place Upgrade.

   1. Download the official Windows 11 ISO or the Windows 11 Media Creation Tool from Microsoft's website.
   2. Mount the ISO file by double-clicking it (or open the tool) and run setup.exe.
   3. Follow the prompts and ensure that "Keep personal files and apps" is selected.
   4. This completely replaces your broken WinSxS component store with healthy system files while leaving your data entirely untouched.
